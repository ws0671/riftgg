# 소환사 검색 설계 구현률 점검

기준: `RiftGG_Summoner_Search_Design_v0.1.md`의 검색·프로필·랭크·갱신 범위. 경기·통계·인증·즐겨찾기는 제외한다.

## 계산 방식

기능·검증 묶음 20개를 같은 비중으로 계산했다. 코드 줄 수나 개발 시간 비율은 아니다. 변경 전 12/20 = **60%**, 변경 후 완료 19/20 = **95%**다. UI·서버 기능 코드는 모두 작성했고 마지막 항목은 운영 환경의 실제 검증이 남아 있다. 세부 항목은 서로 난이도가 달라 이 수치는 대략적인 범위 지표다.

## 완료한 실제 연결 확인

- 로컬 Supabase 추가 마이그레이션 적용 완료. DB reset 없이 기존 데이터를 보존했다.
- 실제 Riot 계정·프로필·랭크 조회 200, 경고 없음.
- 같은 계정의 두 번째 조회는 `source: cache`를 반환했다.
- 존재하지 않는 계정은 404 `ACCOUNT_NOT_FOUND`로 응답했다.
- 수동 갱신 200 직후 다시 갱신하면 429 `REFRESH_COOLDOWN`, 60초를 반환했다.
- 키·응답 원문·원본 IP는 결과 기록에 남기지 않았다.

## 검증 범위

최종 결과: **Vitest 74개 + Playwright 8개 = 총 82개 통과**, 프로덕션 빌드·린트·Deno 타입 검사 통과.

- Vitest: 입력·React UI·함수·실제 PostgreSQL 엔진(PGlite)의 스키마·RPC·권한·롤백·쿨다운 테스트.
- Playwright: 검색·로딩·공유·페이지 복원·404·429·모바일·요청 경합·랭크·부분 실패·수동 갱신·정규 URL 중복 요청 방지.
- 프로덕션 빌드·린트·Deno 타입 검사.
- 브라우저 자동 테스트는 고정 응답이며 실제 Riot 검증과 구분했다.

## 운영에서 확인할 마지막 5%

1. 운영 Supabase에 마이그레이션과 함수를 배포하고 프론트엔드 URL을 연결한다.
2. 배포 주소에서 공유 URL 직접 접속·새로고침·CORS를 검증한다.
3. 프록시가 덮어쓰는 단일 IP 헤더를 확인한 경우에만 `VERIFIED_CLIENT_IP_HEADER`, `CLIENT_IP_HASH_SALT`를 설정한다. 검증되지 않은 X-Forwarded-For를 신뢰하지 않는다. 기본 모드의 전체·검색 키·Riot 예산 제한은 이미 동작한다.
4. 운영 Riot 키의 앱·메서드별 한도와 실제 부하에서 제한 동작을 확인한다.
5. 운영 DB에 pg_cron이 있으면 마이그레이션이 정리 작업을 등록한다. 없는 환경은 외부 스케줄러로 `cleanup_summoner_search()`를 실행한다.

이번 작업에서 원격 DB·공개 호스팅 배포는 실행하지 않았다. 로컬 개발 기능 완료와 운영 검증 완료를 구분하기 위해 100%라고 표시하지 않는다.
