# 최근 경기

PRD §3.3에 따라 소환사 프로필 아래에 최신 경기 목록을 표시한다. 프로필 확인 후 첫 10경기를 자동으로 불러오고, `더 보기`로 다음 10경기를 이어 붙인다. 경기 조회에 실패하면 프로필·랭크와 이미 표시한 경기 목록을 유지한다. 플레이 통계는 후속 범위다.

카드에는 승패, 챔피언, 게임 모드, K/D/A와 KDA, CS와 분당 CS, 아이템 슬롯, 경기 길이와 종료 시각을 표시한다. 작은 화면에서는 아이템·CS를 아래쪽에 배치한다. 챔피언·아이템 이미지의 버전은 서버의 `DDRAGON_VERSION`을 사용하고, 이미지가 없으면 이름이나 아이템 ID를 표시한다.

## 조회와 캐시

- 공개 Edge Function `summoner-matches`가 프로필 응답의 PUUID로 Riot MATCH-V5의 ASIA 호스트를 호출한다. 첫 조회 시각을 다음 페이지에도 넘겨 조회 중 추가된 경기 때문에 페이지가 밀리는 일을 줄인다. 요청·응답 형식은 [Zod 계약](../../../supabase/functions/_shared/matchContracts.ts)을 참고한다.
- 경기 ID 목록은 요청마다 조회하고, 개별 경기 요약은 PUUID와 경기 ID별로 7일간 캐시한다. Riot 원문 대신 해당 플레이어의 카드에 필요한 필드를 저장한다. 검색 기능과 Riot 호출 예산을 공유하고, 같은 소환사의 같은 페이지는 DB 리스로 조정한다.
- 캐시 권한과 정리 함수는 [마이그레이션](../../../supabase/migrations/202611030004_summoner_matches.sql)에 있다. pg_cron이 없는 운영 환경에서는 스케줄러로 `select public.cleanup_summoner_matches();`를 실행한다.

실행과 배포 명령은 [개발·배포 절차](../../common/development.md)를 참고한다.


## 경기 상세

PRD §3.4의 팀별 승패·총 킬과 참가자별 챔피언·이름·K/D/A·CS·아이템·챔피언 피해량·획득 골드를 카드 아래에 표시한다. 한 번에 한 경기만 펼치며 조회한 소환사를 강조한다. 데스크톱에서는 기록과 피해량·골드를 함께 표시하고, 모바일에서는 두 보기로 나눈다. CSS 펼침은 180ms이며 모션 줄이기 설정에서는 즉시 전환한다.

상세는 처음 펼칠 때 같은 함수에 `{ puuid, matchId }`로 요청한다. [상세 캐시 마이그레이션](../../../supabase/migrations/202611030005_match_detail.sql)은 경기 ID별로 팀과 참가자 요약을 7일간 보관한다. 서버는 참가자 ID로 조회 대상을 확인하고 응답에는 강조 여부만 포함한다. 목록과 상세가 Riot 호출 예산을 공유한다. [Riot MATCH-V5](https://developer.riotgames.com/apis#match-v5)
