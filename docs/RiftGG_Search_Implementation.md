# PRD 3.1·3.2 소환사 검색·프로필·랭크 구현 기록

작성일: 2026-11-03

## 범위

초기에는 PRD 3.1만 구현했고, 후속 요청에 따라 검색 설계 v0.1의 프로필·랭크·수동 갱신까지 확장했다. 현재 구현률은 기능별 점검 기준 95%이며, 운영 배포 환경 검증을 별도 항목으로 남겼다. [전체 점검표](./RiftGG_Summoner_Search_Progress.md)를 참조한다.

| 요구사항 | 구현 |
| --- | --- |
| Riot ID와 태그라인 검색 | 공통 폼, 공백·한글 보존, 입력 검증, 버튼·Enter·IME 처리 |
| 한국 서버 | 서버에서 kr만 허용. ASIA에서 계정, KR에서 LoL 프로필 조회 |
| 결과 이동·공유 | `/summoners/kr?gameName=...&tagLine=...`, URL 복사, 직접 접속·새로고침·뒤로 가기 |
| 로딩 | 접근 가능한 스켈레톤·busy 상태, 서로 다른 검색 결과 분리 |
| 존재하지 않는 계정 | ACCOUNT 404와 KR 프로필 404 구분, 입력값 유지 |
| 디자인 | 블랙 토큰, 보라색 포인트, 반응형·키보드 포커스 |
| 랭크 | 솔로·자유 랭크, 티어·LP·승패·승률, 언랭크·조회 실패 구분 |
| 수동 갱신 | 기존 데이터 유지, Mutation, PUUID별 60초 쿨다운 |

## 현재 구현 방식

- 경기·통계·인증·즐겨찾기·테마 전환은 이 검색 설계의 후속 범위다.
- 이름 대응·프로필·랭크 상태·랭크 엔트리를 분리 저장하고, 리스와 원자적 RPC로 갱신한다. 기존 snapshot 테이블은 호환용으로 보존한다.
- `forceRefresh`를 받고 서버와 UI 모두 60초 쿨다운을 적용한다. 실패 시 기존 데이터와 마지막 성공 시각을 유지한다.
- 브라우저·서버 모두 supabase-js를 사용한다. 브라우저 SDK는 검색 시 동적으로 불러오며 요청 취소와 비2xx JSON 오류도 처리한다.
- 정식 이름·태그로 URL을 replace하고 Query 캐시를 이관한다. 이 전환은 같은 검색으로 유지해 추가 요청을 만들지 않는다.
- 일시 장애는 신원이 확인된 계정의 30분 이내 데이터에 한해 경고와 함께 복구한다. 404·키 인증 오류는 오래된 성공으로 숨기지 않는다.
- 전체·검색 키·앱·메서드 단위 제한을 공유 DB에 적용한다. 검증된 단일 IP 헤더와 HMAC salt를 설정한 환경에만 이용자별 제한을 추가한다.

## 프론트엔드 구조 및 스타일 후속 반영

- 페이지는 `src/pages`, 공통 레이아웃은 `src/components/layout`, 검색 UI는 `src/features/summoner-search/components`로 분리했다.
- 조회 설정은 `hooks/useSummoner.ts`, Router·Query 공통 설정은 `app/AppProviders.tsx`로 분리했다.
- 스타일은 기술 사양에 맞춰 Tailwind CSS v4와 공식 Vite 플러그인으로 전환했다. 컴포넌트 CSS 파일은 제거하고 유틸리티 클래스로 옮겼다.
- 블랙 테마는 `styles/tokens.css`의 `@theme`에서 관리하며, 전역 기본 스타일은 `index.css`에 남겼다.
- 초기 Tailwind 전환 시 화면 캡처 3개는 기존 CSS와 픽셀 차이가 없었다. 이후 랭크·갱신 UI를 시안에 맞춰 추가했다.

## 검증과 연결 작업

입력·화면·서버 함수·PostgreSQL 마이그레이션 테스트와 프로덕션 빌드, Deno 타입 검사를 수행한다. 브라우저 E2E는 고정 API 응답을 사용한다.

최종 검증은 단위·통합 74개와 브라우저 8개, 총 82개가 통과했다. 빌드·린트·Deno 타입 검사도 통과했다.

현재 로컬 Supabase에 추가 마이그레이션을 적용했고 실제 Riot 계정·프로필·랭크 조회, 캐시 적중, 존재하지 않는 계정의 404, 수동 갱신 성공과 직후 60초 쿨다운을 확인했다. 공개 호스팅과 원격 DB 변경은 이번 작업에서 실행하지 않았다. 운영 URL·CORS·신뢰 IP·운영 할당량·스케줄러는 배포 단계에서 확인한다.
