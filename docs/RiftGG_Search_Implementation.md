# PRD 3.1 소환사 검색 구현 기록

작성일: 2026-11-03

## 범위

확정한 블랙 디자인을 기준으로 PRD 3.1을 구현했다. 검색 설계 v0.1은 3.2의 랭크와 수동 갱신까지 포함한 확장 설계였으나, 이번 작업은 사용자가 요청한 3.1로 한정했다. 프로필의 이름·아이콘·레벨은 검색 대상 확인을 위한 최소 결과로 포함했다.

| 요구사항 | 구현 |
| --- | --- |
| Riot ID와 태그라인 검색 | 공통 폼, 공백·한글 보존, 입력 검증, 버튼·Enter·IME 처리 |
| 한국 서버 | 서버에서 kr만 허용. ASIA에서 계정, KR에서 LoL 프로필 조회 |
| 결과 이동·공유 | `/summoners/kr?gameName=...&tagLine=...`, URL 복사, 직접 접속·새로고침·뒤로 가기 |
| 로딩 | 접근 가능한 스켈레톤·busy 상태, 서로 다른 검색 결과 분리 |
| 존재하지 않는 계정 | ACCOUNT 404와 KR 프로필 404 구분, 입력값 유지 |
| 디자인 | 블랙 토큰, 보라색 포인트, 반응형·키보드 포커스 |

## 설계안과의 차이

- 랭크·경기·통계·즐겨찾기·수동 갱신·테마 전환은 제외했다.
- 정규화 테이블 전체 대신 검색 결과 snapshot 캐시를 도입했다. 이후 랭크·경기 구현에서 PUUID 기준 테이블로 확장한다.
- `forceRefresh`를 받지 않는다. 5분 캐시 만료 시 재조회한다. UI의 재시도는 실패한 요청만 다시 실행한다.
- 브라우저는 취소 신호·JSON 오류 처리를 명확하게 제어하기 위해 Function REST 엔드포인트를 fetch로 호출한다. 서버의 DB 접근은 supabase-js를 사용한다.
- Riot이 반환한 정식 이름으로 프로필을 표시하되 입력 URL을 자동 교체하지 않는다. 요청 조건을 유지해 별도 재조회를 방지한다.
- 서버 캐시가 만료되면 Riot ID를 재확인하며, 404·장애 시 오래된 결과를 성공으로 반환하지 않는다.
- 제한은 IP를 신뢰하는 대신 검색 키·전체 요청·전체 Riot 요청 기준으로 구현했다. 실제 키 할당량에 따라 조정한다.

## 검증과 남은 연결 작업

입력·화면·서버 함수·PostgreSQL 마이그레이션 테스트와 프로덕션 빌드, Deno 타입 검사를 수행한다. 브라우저 E2E는 고정 API 응답을 사용한다.

이 작업에 실제 Supabase 프로젝트 URL·공개 키·Riot API 키가 제공되지 않아 원격 DB 적용·함수 배포·실제 Riot 계정 조회는 실행하지 않았다. [README](../README.md)의 연결 절차를 완료한 후 실제 API 응답과 캐시 적중을 검증해야 한다. 키 없이 예시 데이터를 실제 결과처럼 보여주지 않는다.
